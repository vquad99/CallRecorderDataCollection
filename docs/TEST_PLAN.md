# Test plan

Status: planned (Phase 0). No test exists yet. Any test not executed is reported as **NOT RUN** with
the reason, and its requirement is not marked VERIFIED (GEN-007).

## 1. Test layers (runbook P, GEN-014)

| # | Layer | Tool (pinned in Phase 1, TECH_STACK.md) | Scope |
|---|---|---|---|
| 1 | Unit | pytest, Vitest | business rules, validation, state transitions, audio calculations |
| 2 | API | pytest + HTTP client against the real app | auth, permissions, CRUD, error handling |
| 3 | Database | pytest against real PostgreSQL | migrations, constraints, transactions |
| 4 | Integration | pytest with real PostgreSQL, Redis, MinIO; provider adapters with test doubles under `tests/` only | storage, queues, adapters |
| 5 | Contract | pytest | provider request/response mapping against the provider's documented schemas (docs/integrations/) |
| 6 | Audio fixtures | pytest + generated WAV fixtures | format, channel mapping, corruption, silence, clipping |
| 7 | Frontend | Vitest + React Testing Library | forms, states, permission-filtered navigation, error handling |
| 8 | End-to-end | Playwright (Chromium, Edge channel; fake media devices) | complete user workflows |
| 9 | Security | pytest + scanners | access control, signed URLs, webhook signatures, CSRF, secrets, dependencies |
| 10 | Load | load tool chosen at Phase 10, staging only | spec 10 / runbook M4 targets |

Screenshots never replace integration tests. One command runs every automated layer except load
(defined in Phase 1); CI runs the same command and fails on any failure.

## 2. Test data rules

- Synthetic participants only (fake names, reserved test numbers); no real personal data anywhere in
  tests or evidence.
- Audio fixtures generated by a script from known signals, so every expected metric is known.
- Test doubles live only under `tests/`; production code never imports them (TA-GEN-01).

Independent inspection for manual audio checks: `ffprobe -v error -show_streams -show_format <file>`;
output saved to evidence.

| D-048 | 2026-11-09 | Accepted | The browser original keeps every channel the capture delivers (32-bit float, interleaved); only the derived file takes channel 1, with no mixing. | D-049 | 2026-11-09 | Accepted | Two reads narrowed to the approved matrix: (1) a participant's consent history is visible to participant managers and to the moderator on an open task with that person only (matrix `consent.view` = A for Moderator), and each participant row says whether this caller may open it (`consent_visible`); (2) storage usage per project is for project administrators (`projects.manage`), not every dashboard role (matrix: other roles' dashboards are "own work"). | Owner's test list, Option B. | D-050 | 2026-11-09 | Accepted | An authenticator code is accepted once only: the time step of the last accepted code is stored (`users.mfa_last_step`) and a code from that step or earlier is refused, including the enrolment code. | D-051 | 2026-11-09 | Accepted | Consent is recorded only by the task's assigned moderator, whatever the caller's role; Super Admin's "F" for consent in the matrix covers viewing and managing consent records, not attesting consent for a conversation they did not take part in. | Existing rule since Phase 3, written down by the Option B sweep. |
| D-052 | 2026-11-09 | Accepted | Request limits at the edge of the API: bodies over 2.5 MB (audio chunks 8 MB) get 413 before they are read; NUL characters in the path, query string or a JSON body get 422; every /api response carries `Cache-Control: no-store` and `Content-Security-Policy: default-src 'none'; frame-ancestors 'none'`. The recorder keeps each chunk under 4 MB. | Option B found a NUL in any text field or search (signing in included) caused a server error, no body size limit, and API answers holding personal data that a browser or shared cache could keep. |
| D-053 | 2026-11-09 | Accepted | Every error screen names the kind of failure (connection problem, no access, not found, not available, something went wrong), shows the server's message and its reference, and offers Try again; a validation error from the server lists each field and what is wrong with it. A page that cannot load its choices (New task) reports it instead of showing an empty list. | Owner's test list, Option C. The page sweep found 17 of 19 error screens without the reference, validation errors that never said which field, and the New task page showing an empty project list when loading failed. |
| D-054 | 2026-11-10 | Accepted | Audio input is checked at the two entry points: an uploaded chunk containing NaN or infinite samples is refused (422 `INVALID_AUDIO`), and the WAV inspector refuses any file that is cut off, has inconsistent format fields or a data chunk that is not whole frames, before samples are read. Over-range float samples (above full scale) are valid capture and are kept in the original. | Owner's test list, Option E. The audio sweep found NaN and infinity accepted on upload, and three damaged-header cases that crashed or were accepted by the inspector. |
| D-047 | 2026-11-09 | Accepted | Known limitation: with the local Docker stack, signed links point at the container name `storage` and do not open in a browser; with Wasabi they work. | Local playback is a development convenience only. |
